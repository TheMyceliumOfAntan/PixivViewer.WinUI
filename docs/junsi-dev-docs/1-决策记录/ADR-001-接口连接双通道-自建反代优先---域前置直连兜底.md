# ADR-001：接口连接双通道：自建反代优先 + 域前置直连兜底

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-02 |
| 决策者 | AI Agent |

## 背景

1.1.0 之前程序只支持自建 pixiv-proxy-api。用户希望反代不可用（服务挂了/被墙）时仍能使用，并能像 Pixeval 那样直连 Pixiv。实测本机网络：TCP 可连 Pixiv IP，但 TLS ClientHello 带 *.pixiv.net SNI 会立即被 RST；同一 IP 换其他 SNI 可正常握手，说明是 SNI 阻断而非 IP 封锁。

## 决策

引入 PixivEndpoints 抽象（App API / Web / OAuth / Image / Static 四个 base，两套映射）。反代模式沿用 {base}/api、/api/web、/api/auth、/image、/static；域前置模式直连 app-api.pixiv.net、www.pixiv.net、oauth.secure.pixiv.net/auth/token、i.pximg.net、s.pximg.net，并用 SocketsHttpHandler.ConnectCallback 映射固定 IP。TLS 层用 TlsFragmentedStream 把 ClientHello 拆成 3 个记录（SNI 开头与中点切分、记录版本 0x0309、100ms 间隔）绕过 SNI 阻断；图片额外补 Referer。反代请求遇到连接异常/超时/5xx/token 刷新网络失败时自动切域前置并保持到本次运行结束。网页登录用本地 CONNECT 隧道（FrontingProxyServer）复用同一分片流，隧道不终止 TLS、不装证书；检测到系统代理时优先用系统代理。设置页可切换模式、编辑「域名 = IP」映射并持久化。

## 备选方案

### 方案 保留 SNI + --host-resolver-rules
- 优点：实现最简单
- 缺点：实测被 SNI 阻断，登录页与图片都拿不到
- 为何不选：已证伪

### 方案 本地 MITM 代理 + 自签证书（Pixeval 旧方案）
- 优点：可控性最强
- 缺点：要关证书校验、代码量大、易踩 WebView2 坑
- 为何不选：用不终止 TLS 的 CONNECT 隧道即可达到同样效果

### 方案 只用自建反代，不做兜底
- 优点：无额外代码
- 缺点：反代挂掉就完全不可用
- 为何不选：不满足需求
